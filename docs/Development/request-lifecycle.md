# Request lifecycle

Every OpenClaw action is a controlled business operation.

1. Request created  
2. Intent classified (taxonomy code)  
3. Contract validated  
4. Skill selected (allowlist)  
5. Dry-run or simulation  
6. Approval if needed  
7. Execution  
8. Verification  
9. Audit log persisted  
10. Incident / resolution knowledge updated  

See also [reliability-rules](./reliability-rules.md) and [learning-loop](./learning-loop.md).
