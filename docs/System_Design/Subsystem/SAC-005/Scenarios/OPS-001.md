# OPS-001 — Read live job estimates from the ERP

**Owner:** SAC-005  
**Actors:** Estimator / sales lead  
**Goal:** See real job-estimate rows from the shop ERP (Odoo) without guessing model names — or use simulate when the ERP is offline.

## Preconditions

- Control-plane stack reachable (Postgres + gateway + orchestrator + web), or apps on host with Compose Postgres — see [OPS-007](../../SAC-009/Scenarios/OPS-007.md).
- `.env` has `ODOO_*` set. Prefer `ODOO_MODE=simulate` for a first pass; use `live` only with a real URL, **correct database name**, and API key/password.
- Optionally confirm **Integrations → Odoo → Test** shows `ok` (or simulated ok).

## Flow

1. Open **Integrations → Odoo**. Confirm URL / DB / credentials (or “from env”). Run **Test connection** if unsure.  
2. Open **Sales / Estimates** (ERP Map → Estimates section) — or **Ontology → Explorer** with type Estimate.  
3. Run **Read estimate** (skill `sales.estimate.read`). Optionally type a **contains** filter (part no or description) and Search.  
4. Table shows part / customer / costs from the ERP — or clearly labeled simulate sample rows.  
5. On failure, read the short error class/message; do not expect raw Odoo RPC dumps in the UI.

## Success

- Rows return with columns the shop understands (estimate id, name/part, partner, amounts/costs as mapped).  
- Live mode uses ERP data; simulate mode shows sample rows plus a warning.  
- Failures show a clear message (`dependency_failure` / auth / circuit) without leaking secrets.  
- Vendor model `customer.estimate` stays inside the connector — UI speaks “Estimate.”

## Failure / edge cases

| Situation | Expected |
|-----------|----------|
| Wrong `ODOO_DB` or bad key | Test / read fails with degraded or down; no silent empty “success” pretending to be live |
| Circuit open after repeated timeouts | Clear “down” / circuit message; cool-off before hammering Odoo again |
| Skill not on allowlist | Execute rejected at facade — broaden allowlist only via a certified change |
