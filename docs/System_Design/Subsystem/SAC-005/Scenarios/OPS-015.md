# OPS-015 — Bind a data-source edge into ontology

**Owner:** SAC-005 · also SAC-006  
**Class:** External (product OPS)  
**Status:** Open  
**Actors:** Admin / product builder (first-party)  
**Goal:** Attach a **data-source** edge (transactions, files, relational extract, later IoT) so ontology properties can be filled via connector bindings — operators still see business vocabulary only.

## Preconditions

- Ontology type exists.  
- First-party data connector (or stub) in catalog.  
- Binding YAML path under product-owned packages.

## Flow

1. Declare/confirm entity properties on the ontology type.  
2. Add bindings mapping properties → data-source fields (adapter-only).  
3. Enable a read skill that uses that connector.  
4. Explorer (or skill execute) returns business columns — not raw source payloads in the UI.

## Success

Data arrives through ontology + skill; public catalog responses omit vendor field maps.

## Failure

Unbound property or disabled connector → clear failure; no silent null-as-success for “live.”
