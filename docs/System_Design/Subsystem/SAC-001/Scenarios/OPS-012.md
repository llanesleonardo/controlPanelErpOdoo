# OPS-012 — Blocked skill / rate limit / allowlist reject

**Owner:** SAC-001  
**Actors:** Estimator or integrator calling the gateway (UI or direct API)  
**Goal:** Prove the front door refuses unknown/non-allowlisted skills and slows abusive callers — without inventing new ERP tools from free text.

## Flow

1. Call a live path that needs an allowlisted skill (e.g. Explorer objects for Estimate, or `POST /skills/execute`) with a **known** allowlisted code such as `sales.estimate.read` — confirm success or documented live path.  
2. Repeat with a **non-allowlisted** or unknown skill / intent code — expect reject or explicit non-live fallback (demo rows + message), never a new invented tool.  
3. Flood the gateway past `RATE_LIMIT_MAX` within `RATE_LIMIT_WINDOW_MS` (same `X-Actor-Id` or IP) — expect HTTP **429** with a clear body.  
4. Confirm responses carry / accept `X-Correlation-Id` and actor is recorded on skill-bound paths.

## Success

- Allowlisted skill can proceed (or clear live failure from ERP/simulate — not a policy invent).  
- Non-allowlisted / unknown code is refused or degraded with an operator-readable reason.  
- Over-limit calls return **429**.  
- Correlation id is present on the response.

## System notes

Gateway: `apps/gateway` · allowlist: e.g. `LIVE_READ_SKILLS` · rate limit: `ActorRateLimitGuard` · headers: `X-Actor-Id`, `X-Correlation-Id`
