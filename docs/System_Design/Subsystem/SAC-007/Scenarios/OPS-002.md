# OPS-002 — Preview a risky write before changing ERP data

**Owner:** SAC-007  
**Actors:** Operator with permission to create tasks (dev-actor stub is fine in lab)  
**Goal:** See what *would* change in the ERP before anyone commits a live write — like dry-fitting a fixture before you cut.

## Flow

1. Bring up Postgres + gateway (+ orchestrator). Use `ERP_MODE` / `ODOO_MODE=simulate` if you do not have a live ERP.  
2. Open **Console** (`/console`). Pick a write intent that supports dry-run (e.g. stock adjust or invoice post from the allowlist).  
3. Set **execution mode = dry_run** and create the task.  
4. Gateway calls orchestrator `POST /skills/dry-run`; task moves `pending` → `running` → `completed` (or `failed`).  
5. Open **Tasks** → task detail. Review **predicted effects**, **warnings**, skill id, and mode.  
6. Copy the **correlation_id**. Open **Logs**, search by that id; confirm gateway (and orchestrator if running) lines.  
7. If an evidence file was written, confirm it under `STORAGE_ROOT/evidence/{correlation_id}/` (default root `./resources/storage/local`).  

## Success

- No silent live ERP write (business data unchanged).  
- Preview is visible on the task (structured effects / warnings).  
- Same `correlation_id` appears on the task, in Logs, and on any evidence file path.  
- Unknown / non-allowlisted intents fail validation without inventing ERP calls.

## Failure / degraded

- Connector unhealthy or `odoo_rejection` / `dependency_failure` → task `failed` with a clear error; fix settings or stay on simulate before retrying.  
- Orchestrator down → dry-run fails visibly; do not treat an empty detail page as “safe to commit.”

## System notes

- APIs: `POST /tasks` (auto dry-run when mode is dry_run), orchestrator `/skills/dry-run`  
- Paths: `LOG_DIR=./resources/logs` · `STORAGE_ROOT=./resources/storage/local`  
- Screens: `/console`, `/tasks/[id]`, `/logs`
