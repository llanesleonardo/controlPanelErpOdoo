# OPS-011 — Find and dismiss estimate issues

**Owner:** SAC-008  
**Actors:** Estimator / office operator (dev-actor stub in lab)  
**Goal:** Pull estimate data problems into the control panel, review them, and dismiss noise — without rewriting the ERP by hand.

**Runtime note:** Implementation is **deferred** ([GAP-02](../../Risks.md)). This scenario is the acceptance story once find/persist/dismiss ships; until then treat runs as blocked.

## Flow

1. Bring up Postgres + gateway (+ orchestrator). Prefer `ERP_MODE=simulate` for a first pass.  
2. Open the **Estimates** section in the control panel.  
3. Run **Find issues**. Wait for completion; note `correlation_id` if shown.  
4. Review the list of **open** issues (stable ids, readable descriptions — no raw Odoo model names).  
5. **Dismiss** one issue that is a false positive or already handled offline.  
6. Confirm the issue moves to dismissed (or leaves the open list) and that **Odoo / ERP estimate rows were not changed**.  
7. Optional: search **Logs** by correlation id; confirm structured trail for the find run.

## Success

- Find persists issues in the control plane (simulate yields deterministic dummies; live uses connector).  
- List shows open (and optionally dismissed) issues.  
- Dismiss updates control-plane status only — ERP untouched.  
- UI language stays product/taxonomy, not vendor model names.

## Failure / degraded

- Runtime not shipped → scenario **Blocked** (record in test report; do not invent a pass).  
- Live connector down → clear failure; simulate still usable for UI/list/dismiss once persist exists.  
- Unknown / non-allowlisted diagnose path → validation error, no free-form ERP call.

## System notes

- Planned APIs: find / list / dismiss on gateway; orchestrator EstimatePort diagnose  
- Storage: control-plane Postgres for issues; optional `STORAGE_ROOT/evidence/…` for find evidence
