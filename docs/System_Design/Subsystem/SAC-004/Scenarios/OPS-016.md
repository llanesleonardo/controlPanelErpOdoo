# OPS-016 — Invoke a logic-source edge as ontology action

**Owner:** SAC-004 · also SAC-005  
**Class:** External (product OPS)  
**Status:** Open  
**Actors:** Operator / analyst  
**Goal:** Run **rules, forecast, or other logic** only as a certified ontology action → allowlisted skill → logic connector — never as free-form model calls from chat.

## Preconditions

- Ontology action linked to a skill that targets a logic-source connector (or stub).  
- Allowlist includes that skill.

## Flow

1. Operator picks ontology action (e.g. “forecast demand for item”).  
2. System resolves skill + logic connector.  
3. Result returns as structured ontology-facing output with provenance (`live|simulate|logic`).  
4. Evidence stores correlation id and connector_id.

## Success

Logic runs only on the governed path; NL cannot invent a new optimizer call.

## Failure

Unknown action / missing skill → reject without calling the logic edge.
