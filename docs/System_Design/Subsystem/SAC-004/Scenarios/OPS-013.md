# OPS-013 — Act on ontology object targeting any SoA

**Owner:** SAC-004 (skills) · also SAC-005, SAC-006  
**Class:** External (product OPS)  
**Status:** Open  
**Actors:** Operator (or automation with policy)  
**Goal:** Run an ontology action that resolves to an allowlisted skill on **whichever** system-of-action connector owns the binding — ERP is a peer, not the only target.

## Preconditions

- Ontology type + action declared; skill registered.  
- At least one SoA connector enabled for that skill (ERP or another).  
- Actor authorized; allowlist includes the skill.

## Flow

```text
  Pick ontology object + action
           │
           ▼
  Resolve skill + owning connector (binding)
           │
     ┌─────┴─────┐
     │ ok        │ missing binding / unknown SoA
     ▼           ▼
  Execute skill   Honest failure
  via connector
```

1. Operator selects an object type/action in UI (or known intent).  
2. System resolves skill code and **connector_id** from ontology bindings — not from hard-coded “always Odoo.”  
3. Skill runs through orchestrator → chosen SoA adapter.  
4. Evidence records actor, correlation id, connector_id, outcome.

## Success

Action completes (or dry-runs) against the **correct peer SoA**; UI never requires the operator to speak vendor model names.

## Failure

Missing binding, disabled connector, or allowlist miss → clear reject; no invented vendor call.
